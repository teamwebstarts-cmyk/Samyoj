# Meta App Review, publish, and live-test runbook

**Date:** 24 Sep 2026  
**App:** Samyoj Meta app, Development mode  
**Purpose:** move from local/test-webhook evidence to real Facebook, Instagram, Lead Ads, and read-only Ads proof.

## Current diagnosis

The Facebook Page and `@teamsamyoj` Instagram account are connected to Samyoj. The Meta Webhooks screen shows the Instagram callback and `messages`, `comments`, and `live_comments` subscriptions enabled. However, Meta also shows that an unpublished app receives only dashboard test webhooks; real production data is not delivered, including events generated by admins, developers, or testers.

Therefore:

- Meta native Instagram Inbox receiving a DM proves the Instagram asset works.
- It does not prove that Samyoj received the webhook.
- Samyoj cannot create an Inbox conversation until Meta sends the POST to the public callback.
- Rewriting the frontend or database is not the correct fix for this restriction.

## Track A — local and dashboard testing without publishing

Use this track to prove callback reachability and keep developing safely.

1. Start the stack:

   ```bash
   bash start.sh
   ```

2. Confirm the public callback shown in `server/.env` is the current random ngrok URL. Do not hard-code yesterday's URL.
3. Confirm:

   ```bash
   curl -s http://localhost:8000/health
   curl -s http://localhost:8000/api/whatsapp/webhook/health
   ```

4. In Meta Developer → Use cases → Instagram API → Webhooks → Instagram, use the **Test** link on the `messages` row.
5. Check the API/tunnel logs for a new POST and check the health timestamp/counter.
6. Repeat with `comments` after the message transport test.

Dashboard test payloads are transport tests. They may not create a normal CRM conversation because Meta can send a synthetic sender/account shape. Do not call the full Inbox flow proven unless a real event is delivered and stored.

For local code confidence, the existing Vitest fixtures cover Instagram message/comment dispatch and ingestion. Keep those as the deterministic fallback; do not add an unauthenticated production webhook-injection endpoint just to simulate Meta.

## Track B — App Review and publish for real events

### 1. Prepare the app and business assets

- Keep the app in Development mode while preparing.
- Use the same Meta app ID configured in the server environment.
- Confirm the Facebook Page `Samyoj` is owned/managed by the testing Business.
- Confirm `@teamsamyoj` is a Professional Instagram account linked to that Page.
- Confirm the ad account is active and connected to the Page.
- Confirm the app has a public Privacy Policy URL, Terms URL, and data deletion/contact instructions.
- Keep the HTTPS OAuth redirect URI registered:

  `https://<codespace>-3000.app.github.dev/settings/facebook/callback`

  Add the production callback only when the production origin exists:

  `https://app.samyoj.com/settings/facebook/callback`

### 2. Request only the permissions Samyoj actually uses

Facebook Page, Messenger, Lead Ads, Instagram messaging/comments, and read-only Ads require the following current Samyoj scope set:

- `pages_show_list`
- `pages_manage_metadata`
- `pages_read_engagement`
- `pages_messaging`
- `leads_retrieval`
- `ads_read`
- `instagram_basic`
- `instagram_manage_messages`
- `instagram_manage_comments`

Do not request these for the current product:

- `ads_management`
- `pages_manage_ads`
- `business_management`
- `instagram_content_publishing`

Those would expand the product scope beyond the implemented Phase 0–5 behavior. Do not claim Instagram publishing or Ads mutation.

### 3. Configure App Review submissions

In Meta Developer → App Review / Permissions and features:

1. Open each requested permission.
2. Select the relevant use case.
3. Add the required business details and explanation.
4. Upload a short screencast for each capability.
5. Submit the permissions for review.

Recommended screencast order:

#### Page and Messenger

- Open Samyoj Settings.
- Connect the Facebook Page.
- Show the Page selected in OAuth.
- Send a Messenger message to the Page.
- Show the conversation in Facebook Inbox.
- Reply from Samyoj and show the reply on Messenger.

#### Lead Ads

- Show the connected Page.
- Show an Instant Form owned by the Page.
- Submit a test lead.
- Show the lead in Contacts → Pipeline with source `Meta Ads`.
- Show that duplicate delivery does not create a second lead.

#### Instagram messaging/comments

- Show the linked Professional Instagram account.
- Send a DM to the account.
- Show it in Instagram Inbox.
- Comment a configured keyword on a test post.
- Show the comment in Instagram Comments.
- Show one private reply and the duplicate/retry protection.

#### Ads read

- Show the connected Page and active ad account.
- Open Samyoj Ads performance.
- Show account selection and the read-only seven-day metrics.
- Show that Samyoj has no create, pause, edit, or budget controls.

### 4. Complete review prerequisites honestly

Meta may require Business Verification, app contact details, test instructions, data-use answers, and a screencast. Complete only the requirements Meta displays for the requested permissions. A green use-case checklist is not the same as approved Advanced access.

Do not submit `business_management` or `ads_management` merely to make the checklist green.

### 5. Publish only after approval

After the needed permissions are approved:

1. Confirm the production callback and privacy URLs.
2. Confirm Page and Instagram webhook subscriptions again.
3. Confirm the Page-level and Instagram-account-level subscriptions.
4. Switch the app to Live/Published.
5. Reconnect the Page once to obtain a fresh token with the approved scopes.
6. Reconnect the linked Instagram account if required.
7. Send new real test events; old events are not replayed automatically.

## Real end-to-end test order after publishing

Run each test separately and record UTC time, organization, Page ID, Instagram ID, ad account ID, and result. Never record tokens, App Secret, OAuth state, or `.env` contents.

### Test 1 — Facebook Messenger

1. A second Facebook account sends a new message directly to the `Samyoj` Page.
2. Confirm the message appears only in Facebook Inbox.
3. Reply from Samyoj within 24 hours.
4. Confirm the reply arrives on Messenger.

### Test 2 — Instagram DM

1. A second Instagram account sends a new DM to `@teamsamyoj`.
2. Confirm it is not only a Message Request in Meta native Inbox; accept the request if required.
3. Send a second new message after acceptance.
4. Confirm it appears only in Samyoj Instagram Inbox.
5. Reply from Samyoj and confirm delivery.

### Test 3 — Instagram comment and bot

1. Create an IG-only keyword automation, for example `PRICE`.
2. A test account comments `PRICE` on a test post.
3. Confirm the comment appears in Instagram Comments.
4. Confirm no WhatsApp keyword automation fires.
5. Confirm at most one private reply is sent for the same comment.
6. Retry the event and confirm no duplicate private reply.
7. Test an old comment beyond seven days and confirm private reply is blocked.

### Test 4 — Lead Ads

1. Submit a test Instant Form tied to the connected Page.
2. Confirm one `META_ADS` Lead appears in Contacts → Pipeline.
3. Confirm attribution IDs are retained where Meta provides them.
4. Redeliver the same lead and confirm idempotency.
5. Confirm no WhatsApp follow-up is sent without phone, consent, active number, and approved template.

### Test 5 — Ads read

1. Open Facebook → Ads in Samyoj.
2. Select the intended active ad account.
3. Compare the last seven days with Ads Manager.
4. Confirm attribution label `7-day click / 1-day view`.
5. Confirm zero leads shows CPL `—`.
6. Confirm there are no mutation controls.

## Honest completion gate

Phase 0–5 is live-proven only when at least one new real event completes each applicable chain:

```text
Meta event
→ public callback POST
→ signature validation
→ organization/channel routing
→ database message/conversation
→ Socket/UI display
→ outbound reply
```

Until then, the status remains code-complete/local-tested but not customer-production-ready.
