# Production fix — 2026-08-15 (webhook + calling)

Live: `https://app.samyoj.com`. VM `samyoj-server` / `asia-south1-c`. App `/home/samyoj/Samyoj` as `samyoj`.

This is an ops + code fix for the outage in `PROD_ERRORS_2026-08-15.md`. It is **not** a claim that customer production is complete.

## What was broken

### 1. Inbound webhook (messages + AI voice)

The API endpoint was healthy. Public GET challenge returned `ping`. Nginx had **zero** `POST /api/whatsapp/webhook` from 13 Aug onward.

Meta’s **app** webhook callback was not `app.samyoj.com`. It was a dead local tunnel:

`https://collision-modified-spur.ngrok-free.dev/api/whatsapp/webhook`

Fields already included `messages` and `calls`. Local `npm run setup-webhook` / `start.sh` had overwritten the **app-level** callback. Production `.env` was already correct (`https://app.samyoj.com/api/whatsapp/webhook`). Meta simply was not posting here.

That also explains inbound voice: user-initiated calls arrive on the `calls` webhook. No POST → AI never answers. WhatsApp can still show a connecting/ringing call.

### 2. Outbound agent call (callback) — SDP

`POST /api/calling/callback` → Meta Graph `138008` / `2593093` **Provided SDP is invalid**.

Browser offer used `addTransceiver('audio')` **plus** `createOffer({ offerToReceiveAudio: true })`, which can emit **two audio m-lines**. WhatsApp Calling allows a **single** audio stream. Chrome also sends lowercase `a=fingerprint:sha-256`, extra SHA-384/512 lines, mDNS `.local` ICE, TCP, and IPv6 — all common Meta rejects.

Handler on that attempt was **AGENT** (human callback), not AI. Permission request had succeeded.

### 3. AI chat on the thread they used

`bot_active = false` (handoff 8 Aug) is **intentional**. Inbox pause/handoff skips the bot on **that conversation**. New conversations still default `bot_active = true`. We did **not** mass-re-enable handed-off chats.

## What we changed

### Already applied on Meta (before code deploy)

Re-ran `npx tsx scripts/setup-webhook.ts` on the VM. App subscription callback is now:

`https://app.samyoj.com/api/whatsapp/webhook`

Fields: `messages`, `calls`, plus the existing template/quality/account set. Public challenge `ping` = 200.

### Code (this workspace → VM)

| File | Why |
|------|-----|
| `server/src/modules/whatsapp/webhook-url.ts` | Treat ngrok/localhost as ephemeral; refuse replacing a live production callback |
| `server/src/modules/whatsapp/meta.service.ts` | Read current app subscription; block ngrok overwrite; pin durable WABA `override_callback_uri`; register app webhook **before** WABA subscribe |
| `server/scripts/setup-webhook.ts` | Same order; log subscribed fields |
| `server/src/modules/calling/whatsapp-sdp.ts` | Sanitize SDP: CRLF, `SHA-256`, drop extra hashes/video/extra audio m-lines (offers), drop mDNS/TCP/IPv6 ICE |
| `server/src/modules/calling/meta-calling.service.ts` | Sanitize `session.sdp` before Graph `connect` / `pre_accept` / `accept` |
| `server/src/modules/calling/webrtc-bridge.ts` | Same sanitize on AI offer/answer |
| `client/src/utils/agentCallRTC.ts` | `addTrack` + `createOffer()` (no `offerToReceiveAudio`); fingerprint/CRLF sanitize |

Webhook health counters stay in-memory (reset on PM2 restart). Durable events table is empty until new inbound arrives — not worth a parallel counter.
