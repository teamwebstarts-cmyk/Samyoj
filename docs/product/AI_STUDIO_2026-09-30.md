# AI Studio — use cases, flows, and architecture

**Date:** 30 September 2026  
**Status:** Discussion spec. Not shipped. Old Content Studio UI, APIs, workers, and tables were removed the same day.  
**Route (kept empty):** `/content-studio` (nav label still **Content Studio** until rename is approved)  
**Decision this doc answers:** What AI Studio *is*, what it must *not* redo, and how it connects to WhatsApp, Instagram, Facebook, and Email.

---

## 1. One-line product

**AI Studio is the creation desk.** A person describes one offer or idea. The desk produces **visuals + channel-ready copy**. Each channel screen still **sends, publishes, or submits**. Studio does not become a second inbox, a second Posts composer, or a second campaign sender.

```text
Brief  →  generate pack  →  human edit  →  hand off to the channel that already ships
```

That split matches how people actually work in 2026: Reddit threads in r/InstagramMarketing and r/socialmedia keep **Canva / CapCut / Claude for making**, and **Meta Business Suite / Buffer / Later for posting**. They do not want a second caption box in a different app.

## 3. Already in Samyoj — do not rebuild

These stay **on the channel screen**. Studio must not grow a parallel Magic / Compose / Send UI.

| Surface | Already there | Studio must not |
|---------|----------------|-----------------|
| Instagram Posts composer | **Magic** polish + generate caption (`instagramApi.posts.captionAi`) | Another caption Magic |
| Instagram Posts | Upload image / reel / carousel, schedule, publish via Graph Content Publishing | A second Posts editor |
| Instagram Comments | Public / private reply UI | Auto-reply from Studio |
| WhatsApp Templates | Create / submit to **this** WABA | Fake “pre-approved by Samyoj” |
| WhatsApp Campaigns | Audience + consent + approved template send | A Studio “broadcast” button |
| WhatsApp Inbox | Human + bot replies, CSW | A second inbox |
| Email Compose / Templates | Gmail send, `{{name}}` preview, consent | A second Gmail composer |
| Facebook Ads | **Read** insights (`/facebook/ads`) | Ad create / boost |
| AI Bots | Chat vs Calling, Train, personality | A second bot trainer |
| Automations | Keyword / welcome / flows | A second flow builder |

**Honest gap:** after Content Studio was wiped, Posts no longer has “pick an image from AI library.” That is a **Studio output**, not a caption Magic clone.

## 4. What Studio uniquely owns (the genuine job)

Studio exists only where channel screens **cannot** do the work today:

1. **Generate media** — still image, **carousel slides** (2–10), optional overlay text on slides. Posts today **uploads** media; it does not **invent** slides.
2. **One brief → many channel packs** — same offer, **rewritten** for Instagram vs WhatsApp template vs email. Not copy-paste of one caption into three boxes.
3. **WhatsApp template *structure*** — header / body / footer / buttons / `{{1}}` examples that Templates wizard does not AI-build today. Submit still happens on **Templates**.
4. **Hand-off payload** — a durable draft the destination page can open (`Use in Posts`, `Open in Templates`, `Insert in Compose`).

If a use case is only “rewrite this sentence,” it belongs on the **existing Magic / composer**, not Studio.

### 5.2 Reddit (what operators actually do)

Threads such as [Which apps are creators using to automate Instagram content (2026)](https://www.reddit.com/r/InstagramMarketing/comments/1sfq7cc/which_apps_are_creators_using_to_automate/) and [tools for posts/carousels quickly](https://www.reddit.com/r/socialmedia/comments/1sk8m0v/what_tools_do_you_recommend_for_creating/):

- **Visuals:** Canva brand templates for carousels; CapCut for Reels; not “one prompt → finished branded post” without a layout system.
- **Captions:** Claude / ChatGPT **draft**, then edit. People already treat caption AI as a **side button**, not a destination.
- **Carousel quality:** [How can I create IG carousels](https://reddit.sentinel-team.org/posts/1tv644x/snapshots/2026-06-05T17%3A56%3A45.257591Z) — good carousels are **hook + 3–5 slides + close**, with a **fixed layout**. Prompt-only carousels look like slop.
- **Scheduling:** Meta Business Suite / Later / Buffer. Samyoj already schedules **inside Posts**. Studio should not grow a second calendar.

**Implication:** Studio v1 = **brief + slide layout + images + adapted copy**. Not a Canva clone, not CapCut, not a scheduler.

### 5.3 Provider limits (fail-closed)

**Instagram Content Publishing** ([Meta](https://developers.facebook.com/documentation/instagram-platform/content-publishing)):

- Professional / Business account. JPEG for images. Shopping tags and filters: **no**.
- Carousel: **2–10** items; crop follows **first** slide; **Reels cannot sit in a carousel**.
- Reels: `media_type=REELS`; Graph Reels tab eligibility is still **short 9:16** (commonly cited 5–90s). Native app may allow longer; **API has not caught up**.
- Stories: `STORIES`; **caption is ignored**.
- Rate: **100 API publishes / 24h** moving window (carousel = 1). Public HTTPS URL for Meta fetch.
- Alt text: images only (from Mar 2025), not Reels/Stories.

**WhatsApp templates** ([Meta](https://developers.facebook.com/docs/whatsapp/business-management-api/message-templates/)):

- Marketing / Utility / Auth. **Meta review**, not Samyoj.
- Unverified portfolio: **250 templates / WABA**; verified: up to **6,000**.
- Media card carousel: marketing only, **2–10 cards**, card body **≤160 chars**, buttons **frozen** after approval.
- Catalog / MPM templates need a **Commerce catalog on the WABA**. Samyoj catalog UI was never Studio; do not pretend Studio can invent catalog SKUs.

**Facebook Page feed:** organic photo / multi-photo is possible with Page token. Samyoj has **no Facebook Posts screen**. Ads page is **insights only**. Studio must not claim “post to Facebook” until that screen exists.

**Gmail:** send only from the **connected mailbox**; contact needs a valid address; consent / permission rules already in Compose. Studio drafts text; **Compose sends**.

**Samyoj campaigns:** WhatsApp-only, fail-closed consent (`optedIn` + source + time + no opt-out). Studio never queues a campaign.

```text
                    │  Brief (offer, language, brand notes)     │
                    │  Artifact type: image | carousel | WA     │
                    │                 template | email pack     │
                    │  Generate → review → save StudioDraft     │
                    └───────────────┬───────────────────────────┘
                                    │ hand-off (no send)
          ┌─────────────┬───────────┼────────────┬──────────────┐
          ▼             ▼           ▼            ▼              ▼
   IG Posts        WA Templates   WA Campaigns  Email        (later)
   composer        submit Meta    pick template Compose      FB Posts
   Magic stays     stays here     stays here    stays here   does not exist
   here
```

**Suggested objects (when we implement — not in DB today):**

| Object | Role |
|--------|------|
| `StudioBrief` | Prompt, language, org, optional product photos |
| `StudioPack` | Generated assets + per-channel copy variants |
| `StudioAsset` | Image / slide (public URL Meta/Gmail can fetch) |

**Credits:** one ledger action (e.g. `ai_studio`) on generate. Do not bill caption Magic twice if Studio already wrote the caption — Posts Magic remains a **cheap in-composer** polish.

## 7. Use cases that are worth building

Each case: **why Studio**, **flow**, **where it lands**, **limits**. Skip anything that is only Magic.

### UC-1 — Instagram carousel from one offer (primary)

**Why Studio:** Posts can upload slides; it cannot **layout a 5-slide story**. Reddit’s bottleneck is “assemble the carousel,” not “polish the last caption.”

**Flow:**

1. User opens **AI Studio** → type: **Instagram carousel**.
2. Brief: product, offer, language (EN / HI / Hinglish), 4–7 slides.
3. Optional: upload **real photos** (preferred). AI fills missing slides / overlay text on a **fixed template** (hook, points, close).
4. Preview grid (square / 4:5 — user picks; first slide sets crop).
5. Caption **suggestion** on the pack (not Magic). User can edit.
6. **Use in Posts** → `/instagram/posts` with `mediaType=CAROUSEL`, slides attached, caption filled.
7. User **schedules or publishes in Posts**. Magic is still there if they tweak the caption.

**Limits:** 2–10 slides; no Reels inside carousel; JPEG; 100 posts/day; no shopping tags.

### UC-2 — Single Instagram image post (visual-first)

**Why Studio:** user has no photo, or wants a generated hero **plus** a starting caption. If they **already have** a photo in Posts, they use **upload + Magic**, not Studio.

**Flow:** Brief → generate 1–3 image options → pick one → **Use in Posts** as `IMAGE` + suggested caption → publish in Posts.

**Do not:** open Studio from the Magic button.

### UC-3 — WhatsApp marketing template (copy + header image)

**Why Studio:** Templates page has no Interakt-style “make the whole template.” Campaigns can only send **already approved** templates.

**Flow:**

1. Studio type: **WhatsApp template**.
2. Brief + category hint (Marketing vs Utility — user confirms; miscategorization is a Meta risk).
3. Output: `name` suggestion, body with `{{1}}` / `{{name}}`, optional header image, 1–2 buttons, **example values** for review.
4. **Open in Templates** with fields filled.
5. Human edits, **submits to this WABA**. Status stays on Templates.
6. Later: Campaigns picks the **APPROVED** template. Studio is out of the send path.

**Limits:** Meta approval; carousel templates need 2–10 cards and freeze button types; catalog templates need a connected catalog.

### UC-4 — Same offer, three channels (the cross-channel case)

**Why Studio:** this is the only place a **pack** is cheaper than three composers. Still **three hand-offs**, not one “post everywhere” button (policies differ).

**Flow:**

1. One brief: “Diwali 20% off this weekend, Jaipur store.”
2. Studio produces:
   - IG carousel pack (UC-1)
   - WA template draft (UC-3) — **not** the IG caption pasted into WhatsApp
   - Email subject + body with `{{name}}` (UC-5)
3. Three buttons: Use in Posts / Open in Templates / Insert in Compose.
4. User may ship **only Instagram** this week. That is fine.

**Do not:** auto-publish all three. Do not send WhatsApp free-form outside CSW.

### UC-5 — Email pack (compose or save template)

**Why Studio:** Compose is for **sending**; Templates is for **reuse**. Neither generates a campaign-style email from a brief.

**Flow:** Brief → subject + body + variables → **Insert in Compose** (To still picked from contacts) **or** **Save as email template**. Send still requires connected Gmail + consent.

**Limits:** no HTML blast engine; Gmail daily caps; mock preview cannot send.

### UC-6 — Comment / inbox reply (explicitly **not** Studio v1)

Manychat puts this in **AI Replies**. Samyoj already has Comments + Inbox. A later **“Suggest reply” on the thread** is the right UX. Putting it in Studio would force agents to leave the conversation.

**If we add it later:** button on the comment/DM row → draft → approve → send. No Studio calendar.
